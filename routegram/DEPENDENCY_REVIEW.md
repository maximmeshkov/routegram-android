# RouteGram 0.2.0: upstream и проверка сборки

## Принятое ограничение

Обновлять upstream-проекты целиком до выбранного выпуска. Не менять по отдельности
зависимости Telegram, его сборочные плагины и native-пины. Наш прокси, Android-обёртка
и сборка живут отдельно в `routegram/`; интеграция с клиентом остаётся минимальной.
Это явное решение пользователя от 4 ноября 2026. Индивидуальные обновления библиотек
отменены и не входят в 0.2.0.

## Зафиксированные upstream

- Telegram **13.1.1 (7237)**: официальный [коммит DrKLO
  3de37c8](https://github.com/DrKLO/Telegram/commit/3de37c8cfb039452be7398909461da6288babf15).
  Отдельного Git-тега на нём нет. Gradle 8.13, AGP 8.13.2, Kotlin 2.1.0
  и остальные зависимости взяты из этого коммита целиком.

  оригинальный [Flowseal/tg-ws-proxy 1.11.4](https://github.com/Flowseal/tg-ws-proxy/tree/2085861957070eeea07990a522b29f42e5230210),
  без изменений протокольных исходников.
- CPython 3.13.18 и runtime-пакеты закреплены внутри модуля в
  [upstream.json](libtgwsproxy/upstream.json); архивы проверяются по контрольным суммам.
  Модуль поставляет готовые библиотеки в APK; пользователю Python устанавливать не надо.

## Отличия форка

Минимум приложения — **Android 9 / API 28**. Подвал содержит `RouteGram 0.2.0 by MLab`
со ссылкой на репозиторий. Вызов нового `ConnectionsManager.setProxySettings`

совпадают побайтно. В корневом `settings.gradle` сохранено подключение
`apply from: 'routegram/settings.gradle'`.
Порог API 28, поля версии и зависимость от glue подключаются через наш
`android-overlay.gradle`, вызванный из `routegram/settings.gradle`.
Проверка настоящего Gradle DSL подтвердила минимум для defaultConfig и flavors,
поле версии 0.2.0 и зависимость от glue; лог — `build/routegram-0.2.0/overlay-probe.log`.
Отчёт зависимостей — `build/routegram-0.2.0/upstream-dependency-parity.json`.
Все 19 native/media-submodules совпадают с SHA выбранного upstream и не имеют
правок внутри; отчёт — `build/routegram-0.2.0/submodule-parity.json`.

## Дефект тёмной темы

Пользователь сообщил о пропавшем тексте на телефоне. UIAutomator видел TextView,
но контраст их пиксельных областей был нулевым. Дефект также воспроизведён в APK
0.1.6 на Android 9 после переключения темы, до новой базы и прокси.

В Windows checkout файлы `.attheme` получили CRLF вместо исходных LF. Парсер
Telegram включает завершающий CR в число и возвращает 0 при ошибке преобразования;
цвет становится прозрачным. `.gitattributes` теперь сохраняет LF для этих ресурсов.
Код парсера и UI для этого не изменён.

Контрольный APK отличается от прежнего только пятью файлами тем с окончаниями LF;
все DEX и `.so` побайтно совпадают. На Android 17 тёмная тема восстановилась:
контраст трёх текстовых областей 207/231/231 вместо 0/0/255; результат PASS.
Диагностический код и результаты: `build/routegram-0.2.0/theme-ab-test.py`,
`build/routegram-0.1.7/check-render.ps1`, `verification/api37-lf-only-render-result.json`.

## Проверки

Итоговая сборка клиента, AAR и тестового APK завершилась успешно
(`build/routegram-0.2.0/final-build.log`, 6 мин 59 с).
Модуль повторно собран штатными инструментами Telegram 13.1.1 и прошёл четыре
теста: AES, отказ при занятом порте и три stop/start, настоящий MTProto
req_pq_multi/resPQ с проверкой nonce, отдельный обмен через WebSocket.
В последнем тесте растёт WS-счётчик, TCP-fallback-счётчик остаётся неизменным.

| Устройство | Страницы памяти | Результат | MTProto по умолчанию / WebSocket |
|---|---:|---|---:|
| Телефон, Android 16 / ARM64 | 4 КБ | 4/4 | 453 / 72 мс |
| Эмулятор, Android 9 / x86_64 | 4 КБ | 4/4 | 537 / 101 мс |
| Эмулятор, Android 17 / x86_64 | 16 КБ | 4/4 | 993 / 127 мс |

Логи и метаданные: `build/routegram-0.2.0/verification/*-instrumentation.txt`,
`*-protocol.txt`, `*-tests.json`. SHA-256 тестового APK:
`72f222264b31494618760c6de332e2daa8dee720a2daa129ca5759744c32203a`.
Это проверка модуля; запуск конечного APK клиента проверяется отдельно.

Конечный APK установлен поверх прежних версий без очистки данных на всех трёх
устройствах. В каждом случае журнал показывает автоматическое применение
`127.0.0.1:1443`, затем состояние «Подключено», без аварии приложения.
На телефоне проверены тёмный стартовый экран, экран входа и цифровая клавиатура;
на Android 9 — тёмная форма ввода номера, на Android 17 — обе темы стартового экрана.
Текст виден визуально и в измерении контраста: на телефоне 218/99/126 для трёх
текстовых областей экрана входа. Снимки с личными данными не предназначены для публикации.
Результаты: `verification/*-app.json`, `*-app-log.txt`, `*-render-result.json`
в каталоге `build/routegram-0.2.0/`.

APK: **106 703 576 байт**, SHA-256
`b51f24b844107fd5e3c633a905087a8a745d54e81825debc55d5e36044981cfe`.
Пакет `com.routegram.messenger.web`, versionCode 72379, Telegram 13.1.1,

тем имеют LF; строка версии и ссылка MLab присутствуют в DEX.
Проверка архива и подписи — `build/routegram-0.2.0/final-artifacts.json`.

## Подготовка выпуска

Аннотация будущего тега — [release-0.2.0.txt](release-0.2.0.txt).
Пользователь разрешил merge и обновление submodules, без создания коммита,
тега и push. Инструкция обновления модуля — [libtgwsproxy/README.md](libtgwsproxy/README.md).

Переписка, медиа, смена Wi-Fi/мобильной сети и нажатие ссылки в настройках после
входа требуют пользовательской проверки; сценарии перечислены в
`RouteGram-0.2.0-testing.txt` в корне. Агент не вводил код входа и не отправлял сообщения.
Успешный протокольный тест не доказывает обход блокировок во всех сетях.

После сборки выполнен отдельный [прогон переподключений](RECONNECT_REVIEW.md)
на телефоне: переключения Wi-Fi/мобильной сети, полный офлайн и возврат из фона.
В мобильной сети действовали белые списки, Wi-Fi использовал обходы роутера.
Восстановление наблюдалось, но постоянное соединение в фоне не подтверждено.
